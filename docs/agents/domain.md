# 领域文档与架构决策消费规范

工程技能在探索代码库与推演设计时，必须遵循本项目的领域设计与架构决策记录。

## 探索前置阅读清单

- 根目录 **`CONTEXT.md`**：记录核心领域模型、通用语言（Ubiquitous Language）与名词定义。
- 架构决策记录 **`docs/adr/`**：阅读与当前改动模块相关的历史架构决策（ADR）。

> **说明**：若上述文件尚不存在，**请静默继续，切勿主动警告缺失或强行预建空文件**。`/domain-modeling` 技能将在后续出现确定的领域术语或重大决策时按需延时创建。

## 目录骨架约定（单上下文仓库）

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxxx.md
│   └── 0002-xxxx.md
└── src/
```

## 领域专业名词约束

在生成 Issue 标题、重构建议、设计假设或测试用例时，必须严格使用 `CONTEXT.md` 锁定的标准领域术语，严禁擅自引入同义异名。

## ADR 决策冲突显式上浮

若当前实现逻辑或提案与既有 ADR 产生冲突，严禁静默覆盖，必须显式在输出中注明冲突背景与重新评估理由：

> *与 ADR-000x（如：基于 SSH 协议直连目标机）存在冲突 —— 提请重新评估审议，原因为……*
