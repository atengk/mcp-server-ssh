# 0013. CLI 引导标志与全景诊断中枢架构

## 背景与决策 (Context & Decision)

`mcp-server-ssh` 作为通过 NPM 分发的可执行二进制工具（`bin: { "mcp-server-ssh": "./dist/index.js" }`），开发者常在终端通过 `npx @atengk/mcp-server-ssh` 或全局安装调用。然而在早期版本中，服务入口未对命令行参数进行任何拦截与解析，导致开发者执行 `--help`、`--version` 或自检命令时，程序直接进入 stdio 传输并静默挂起等待 JSON-RPC 消息，造成“工具卡死”的严重可用性缺陷。同时，当 AI 客户端因网络或认证配置错误无法建连时，开发者缺乏直接的诊断探针来快速排障。

为此，我们做出如下架构决策：**引入零依赖 CLI 前置分流引擎与四维全景自检诊断中枢 (Self-Inspection Doctor)**：
1. **原生零依赖参数解析**：基于 Node.js 18+ 内置原生模块 `node:util` 的 `parseArgs` 实现命令行选项提取，100% 杜绝引入 `commander`、`yargs` 等重型第三方 CLI 依赖；
2. **严格长短标志约束**：仅且严格支持标准长短选项（`-h, --help`、`-v, --version`、`--doctor`），拒绝模糊的裸词子命令，避免与宿主执行参数混淆；
3. **四维全景自检诊断套件 (`--doctor`)**：
   - **Runtime 运行时环境**：校验 Node.js 版本（是否满足 `>=18.0.0`）、底层操作系统类型、CPU 架构；
   - **本地 OpenSSH 资产与 Agent**：检测 `~/.ssh/config` 是否存在与可读、本地常用私钥（`id_ed25519`, `id_rsa` 等）就绪情况、`SSH_AUTH_SOCK` (SSH Agent) 运行状态；
   - **环境变量合规性**：调用 `parseEnv()` 校验当前配置，验证端口范围、超时设置以及严格布尔类型合规性；
   - **目标连通性探测 (若配置了 `MCP_SSH_HOST`)**：尝试向目标主机发起 TCP 端口握手与 SSH 认证探测（限制 5000ms 熔断保护），评估往返网络延迟；
4. **安全脱敏与规范分流**：
   - 诊断报告与帮助信息采用标准化格式输出至 `stdout`，密码、私钥等凭据 100% 实施脱敏掩码；
   - `--help` 与 `--version` 执行后正常 `process.exit(0)`，`--doctor` 发现致命阻断错误时返回退出码 `1`；
   - 未携带任何 CLI 辅助标志时，程序平滑穿透启动标准 MCP 服务。

## 权衡考量 (Considered Options)

- **关于 CLI 框架选型**：
  - 选项 1：引入社区成熟库 `commander` 或 `cac`。生态丰富，但增加安装包体积与供应链依赖链条。
  - 选项 2：采用 Node.js 18+ 原生 `util.parseArgs`（已采纳）。在无需复杂嵌套多级子命令的场景下，原生实现零成本且具备完整的类型安全。
- **关于 `--doctor` 连通性探测深度**：
  - 选项 1：仅做本地轻量检查。无法解答“为什么 Agent 连不上远程服务器”。
  - 选项 2：深度探测网络握手与鉴权（已采纳）。集成 5000ms 短超时保护，能一站式捕获网络防火墙拦截、密码错误或密钥不匹配等最核心的痛点。

## 后果与影响 (Consequences)

- 优势：
  - 彻底终结了命令行执行 `--help` / `--version` 假死的恶劣体验；
  - 赋予开发者与 DevOps 运维一键故障自检能力，将排障耗时从小时级降低至秒级；
  - 架构完全模块化解耦，保持装配入口 `src/index.ts` 干净精悍。
- 代价：
  - 需要在代码库维护 `src/cli/` 独立子模块并保持高测试覆盖率。
