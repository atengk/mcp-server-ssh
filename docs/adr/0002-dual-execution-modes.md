# 0002. 采用无状态 Exec 与交互式 PTY Session 双模执行架构

## 背景与决策 (Context & Decision)

针对 AI Agent 操作远程 Linux Shell 的场景，单一的有状态 Shell 容易因不可预知的输出流阻塞或上下文错乱导致超时，而单一的无状态 Exec 又无法处理需要交互输入（如交互式密码、确认向导）的命令。因此，我们决定采用“无状态 Exec 为主，持久 PTY Session 为辅”的双模并行架构，并在无状态 Exec 中默认使用登录 Shell 包装（`bash -l -c`）以完整继承用户环境变量与 PATH。

## 权衡考量 (Considered Options)

- **选项 1：纯持久化 Shell（单一终端会话）**。无法精确获取命令的退出码（Exit Code），需借助复杂的提示符正则表达式解析命令完成标记，极易因非标准提示符崩溃。
- **选项 2：纯无状态 Exec**。无法执行任何需要二次交互确认或长时间等待输入的运维命令。
- **选项 3：双模并行（已采纳）**。默认暴露 `ssh_exec` 处理 90% 的自动化与幂等排查任务，精准返回退出码与标准错误；同时提供 `ssh_session_*` 支撑复杂交互终端需求。

## 后果与影响 (Consequences)

- 优势：绝大多数命令具备高可靠性、确定性退出码与隔离执行环境，彻底解决 `PATH` 丢失导致 `command not found` 的痛点。
- 代价：服务端需要同时维护单次通道连接池与常驻会话表两套生命周期管理逻辑。
