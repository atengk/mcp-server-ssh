# 0009. 工具集低频收敛与杀手级能力分层扩展

## 背景与决策 (Context & Decision)

随着 MCP 客户端对 Token 上下文消耗的敏感度提升，过多零散的微工具会增加 LLM 的决策负担与幻觉概率；同时，单纯的基础命令与单文件读写无法满足现代 AI Agent 对内网穿透、批量传输与系统感知的核心诉求。我们决定保持核心业务工具的原子化隔离，合并低频元数据发现工具，并分层引入四大杀手级扩展能力（系统体检、目录流式同步、端口转发隧道、文本差异补丁）。

## 权衡考量 (Considered Options)

- **选项 1：保持全量零散微工具并不做合并**。会导致 LLM 工具注册清单持续膨胀（超过 20+ 个），低频工具（如单独读取 ssh_config）长期闲置并占用 Token。
- **选项 2：过度合并为粗粒度“上帝工具”（如统一的 ssh_file_manager）**。导致单个工具的 JSON Schema 过载，分支复杂，LLM 在参数校验与危险操作安全拦截时容易失控。
- **选项 3：原子化核心操作 + 聚合低频发现 + 关键能力演进（已采纳）**。将 `ssh_list_connections` 与 `ssh_list_config_hosts` 统一收敛为兼具活跃连接与静态别名发现的统一目标视图；同时为 `SessionService` 引入提示符等待（Expect Pattern），并落地端口转发、系统体检、目录同步与差异补丁四大杀手级工具。

## 后果与影响 (Consequences)

- 优势：大幅削减 LLM 无谓的上下文开销；极大强化 Agent 对远程内网和服务器全局状态的操控力；符合最小职责与分层解耦原则。
- 代价：需要新增针对隧道生命周期（KeepAlive、动态端口映射）的管理机制，以及统一的文本 Diff 算法。
