# 0003. 前置命令安全拦截与 64KB 双端输出防爆策略

## 背景与决策 (Context & Decision)

赋予 LLM 远程 Linux 执行权限具有重大潜在风险，模型幻觉可能诱发灾难性破坏；同时，高吞吐命令可能产生数万行输出撑爆 LLM 的上下文窗口。我们决定在 MCP 核心层前置内置 `SafetyGuard` 致命命令黑名单引擎，并在数据返回侧实施 64KB 智能截断（保留头部 8KB 与尾部 56KB，自动剥离 ANSI 终端彩色转义字符）。

## 权衡考量 (Considered Options)

- **安全拦截策略**：
  - 自由放行：完全依赖 Linux 原生权限，但 root 或宽泛 sudo 登录下毫无容错空间，风险过大；
  - 纯确认模式：每次命令都要求人机交互确认，打断自动化执行流；
  - 前置规则拦截（已采纳）：自动阻断全盘强删、磁盘破坏、关机重启等毁灭性操作，支持 `dry_run` 与自定义扩展，平衡自主性与安全性。
- **输出截断策略**：
  - 纯前端截断（丢弃尾部）：丢失报错堆栈与最新日志，破坏排查价值；
  - 双端截断保护（已采纳）：保留启动环境与最新报错信息，并附带明确截断警告与替代指引。

## 后果与影响 (Consequences)

- 优势：有效封堵了致命级系统事故，并在终端巨量日志场景下强保 LLM 客户端不崩溃。
- 代价：需要定期维护黑名单模式，极少数包含复杂参数的高级命令需要支持自定义白名单豁免机制。
