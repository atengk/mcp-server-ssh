# 0008. 采用纯 JS 流式 Tar 打包实现目录级传输并拒止原生模块

## 背景与决策 (Context & Decision)

当前 SFTP 文件传输服务仅支持单个文件的读写与上传下载，在处理大型项目工程、依赖包或深层日志目录时面临严重瓶颈。为了实现目录树级的高速双向同步，同时避免破坏跨平台零编译构建的底线，我们决定引入无 Native 编译绑定的纯 JavaScript `tar-stream` 模块配合 Node 原生 `zlib`，坚决拒止 `node-pty` 或 `systeminformation` 等 C++ 原生本地宿主模块。

## 权衡考量 (Considered Options)

- **选项 1：纯 SFTP 协议逐文件递归传输**。优点是零新增依赖，缺点是高延迟网络下每个文件都需要多次往返握手（创建目录、打开文件、写块、关闭），目录同步极其缓慢且易中断。
- **选项 2：引入 C++ 原生编译模块（如 node-pty / node-tar 的 native 绑定）**。不仅无法作用于远程 Linux 系统，还会破坏 NPM 一键 `npx` 免编译安装与各系统架构分发的一致性，属于严重的反模式伪需求。
- **选项 3：纯 JS 流式 Tar 打包结合管道（已采纳）**。使用无原生依赖的纯 JS `tar-stream`，在内存中完成打流并通过标准输入输出直接与远程 Linux 系统原生的 `tar` 管道对齐（或经由 SFTP 流），既能实现数十倍的传输性能飞跃，又 100% 保持轻量与跨平台免疫性。

## 后果与影响 (Consequences)

- 优势：目录上传与下载效率提升 10~50 倍；打包与解压过程在内存流中原子化完成，避免在宿主机产生临时中间文件；安装体积无显著增加。
- 代价：需要管理流的背压（Backpressure）与异常熔断，且需对目标远程主机是否具备 `tar` 命令做好前置探测与容错。
